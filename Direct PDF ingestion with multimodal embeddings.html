Direct PDF ingestion with multimodal embeddings, no OCR

Idea

Today, a PDF is usually sent to OCR first, and the extracted text is embedded. OCR flattens tables into loose text and drops graphs and their axes. We want to remove the OCR step.

Instead, each PDF page is saved as a page image and sent straight to a multimodal embedding model. The model reads the page as a picture, so the table layout, the headings and the graphs stay intact in the vector. A text question is embedded by the same model and compared with the page vectors to find the right page.

Usual way

PDF→OCR→Text→Embedding
  • Table structure is lost in the text
  • Graphs and axes are not captured
  • OCR errors pass into the embedding

Our way

PDF→Page images→Multimodal embedding
  • No OCR step
  • Tables and graphs are embedded as they look
  • One model for page images and text questions

The PDFs

Each PDF has headings and also contains tables and graphs with an x-axis against a y-axis, so the documents are well mixed: text, tables and charts on the same pages.

Settings used

SettingValueWhat it means
MAX_SOFT_TOKENS1120Maximum number of tokens the model uses to represent one image. Allowed values are 70, 140, 280, 560 and 1120, so 1120 is the highest (most detail, slowest).
VECTOR_SIZE768Size of each embedding vector, which is the embedding dimension: every image is converted into 768 numbers.
BATCH_SIZE2Images embedded per batch. Each batch is upserted to Qdrant right after, so an interrupted run keeps its progress.
COLLECTIONscanned_pdfQdrant collection name.
